작성: 2026-11-22 · 기준: `sub_v9_blipA.zip`의 `models/haiku_config.json`, `model.py`

## 1. 파이프라인

```
질의 문장
 → **학습한** SigLIP-base-384 검색 (상위 10장)
 → 조건 분해 재정렬 (조건 12종, 비중 3.2)
 → 학습한 BLIP ITM 재정렬 (10장 전부, 점수 비중 0.1) — `sub_v9_blipA.zip`은 v4·v6의 BLIP(A), `sub_v9.zip`은 v7의 BLIP(D)
 → OWL-ViT 좌우·상하 점검 (상위 2장, 확신도 0.1 / 여백 0.06)
 → 복수 관계 점검 (상위 2장, "두 X가 한 Y의 위·아래·왼쪽·오른쪽" 문장만)
 → 상위 5장
```

### 3-2. 복수 관계 점검 (팀원 방법)

- 대상: "두 X가 한 Y의 위/아래/왼쪽/오른쪽" 문장. 기존 OWL 점검은 같은 종류가 여러 개면 건너뛰었습니다.
- 파서(`parse_plural_plan`)와 상자 판정(`plural_geometry`, 여백 0.08)은 팀원 원 실험 코드를 그대로 사용했고, 검출기만 Grounding DINO → 이미 탑재된 OWL-ViT(여러 상자)로 바꿨습니다.
- 주체 상자가 정확히 2개, 기준 상자가 정확히 1개일 때만 판정하고, **1위가 위반이고 2위가 만족일 때만** 교환합니다.

| | 대상 문장 | 교환 | 고침 | 망침 |
|---|---|---|---|---|
| 개발 | 22 | 1 | 1 | 0 |
| 검증 | 37 | 3 | 3 | 0 |

### 3-3. SigLIP 미세조정 (v8에서 추가)

v7까지 검색과 조건 재정렬을 맡는 SigLIP은 사전학습 그대로였습니다 (BLIP만 학습). 테스트에서는 정답이 최종 5장에 드는 비율이 61%뿐이라, 이 단계를 형제 이미지 구별에 맞춰 학습했습니다.

| 항목 | 값 |
|---|---|
| 학습하는 부분 | 이미지·문장 인코더의 마지막 4층 + 출력 헤드 (온도·편향은 고정) |
| 배치 | 32장, 형제 묶음끼리 모아서 구성 (배치 안 오답이 형제 이미지·형제 문장) |
| 손실 ① 문장 전체 | SigLIP sigmoid 손실 |
| 손실 ② **조건 문구** | 이미지마다 문장에서 뽑은 조건의 정답 문구("a green tape measure")가 대조 문구("a red tape measure" 등)보다 높은 점수를 받도록 하는 교차 엔트로피. 추론 때 조건 재정렬이 쓰는 바로 그 비교입니다. 조건 12종, 이미지당 최대 6개, 대조 문구 최대 4개, 비중 2.0 |
| 학습률 / 에폭 | 1e-5 (처음 10%는 서서히 올림) / 8 |
| 옵티마이저 | AdamW, 가중치 감쇠 0.01, fp16 |

SigLIP 단계만 잰 점수 (BLIP 없이, 후보 4,000장, 조건 비중 3.2):

| | 검색만 1위 (개발 / 검증) | +조건 재정렬 점수 | 1위 정답률 | 5위 안 |
|---|---|---|---|---|
| 사전학습 그대로 (v6·v7) | 0.284 / 0.273 | 0.4902 / 0.4826 | 0.334 / 0.328 | 0.912 / 0.904 |
| 문장 전체만 학습 | 0.336 / 0.329 | 0.5107 / 0.5153 | 0.351 / 0.357 | 0.929 / 0.934 |
| **문장 + 조건 문구 학습 (v8)** | **0.351 / 0.335** | **0.5350 / 0.5395** | **0.372 / 0.376** | **0.954 / 0.963** |

- 개발 +0.045, 검증 +0.057로 둘 다 올랐고, 조건 비중은 3.2가 그대로 가장 좋았습니다.
- 전체 파이프라인 정상 동작 확인(후보 4,000장): v7 0.9634 / 0.9692, v8 0.9609 / 0.9701, 형식 정상. 이 점검은 BLIP이 질의를 학습에 쓴 상태라 절대 점수가 높게 나오며, 동작 확인용입니다.
- 추론 코드와 모델 크기가 같아 실행 시간은 v7과 같습니다.

v8과 같은 방법에서 학습하는 층과 에폭만 늘렸습니다 (마지막 4층 → **6층**, 8에폭 → **10에폭**, 나머지 동일).

SigLIP 단계 점수 (BLIP 없이, 후보 4,000장, 조건 비중 3.2):

### 3-5. v7이 리더보드에서 떨어진 이유와 BLIP 되돌리기

- v7의 제출 CSV를 v6와 비교하면, 후보 범위는 같은데(5장 중 4장 이상 같은 질의 91%) **1위가 2,445개(30.6%) 바뀌었습니다.** 바뀐 1위의 95%는 v6의 5장 안에 있던 이미지라, BLIP이 순서를 뒤집은 것입니다.
- BLIP D의 로컬 이득은 개발 +0.006, 검증 +0.005로 오차 범위 수준이었습니다. D는 이미지 인코더까지 학습해서 학습 이미지를 더 강하게 외웠고(학습에 쓴 큰 묶음 140질의에서 1위 139개, A는 124개), 처음 보는 테스트 이미지에는 그만큼 통하지 않은 것으로 판단합니다.
- 그래서 **`sub_v9_blipA.zip`은 BLIP을 리더보드에서 검증된 A(v4·v6)로 되돌렸습니다.** SigLIP 학습의 로컬 이득(+0.07~0.09)은 오차 범위를 크게 넘고, 학습에 쓰지 않은 형제 묶음(검증)에서 확인됐습니다.

| 파일 | SigLIP | BLIP | 비고 |
|---|---|---|---|
| `sub_v9_blipA.zip` | v9 | **A** (v4·v6) | **제출 권장** |
| `sub_v9.zip` | v9 | D (v7) | 비교용 |

## 5. 분석으로 알게 된 것

- **테스트의 형제 묶음은 약 40~64장** (제출 CSV에서 함께 예측된 이미지를 묶어 추정). 학습 데이터는 4장 또는 8장입니다.
- v6 테스트 결과: 정답이 5위 안에 드는 비율 61%, 그 안에서 1위로 고르는 비율 46% (로컬 검증은 99%, 78%).
- 검색과 조건 재정렬을 맡는 SigLIP은 v7까지 사전학습 그대로였습니다. v8에서 이 부분을 학습했습니다 (3-3).
- 팀원 실험 결과(`sibling_results.zip`)를 다시 계산해 보면, S0와 S1의 점수를 합쳤을 때 1위 정답이 527 → 547로 늘어납니다 (0.7564 → 0.7750). 다르게 학습한 재정렬 모델 둘을 합치는 방향이 유효하다는 근거입니다.

## 6. 규칙 점검

- 추론 중 외부 API·생성형 LLM 없음, 외부 데이터 없음 (공개 사전학습 가중치만 사용).
- 질의마다 독립적으로 예측합니다. 다른 질의의 예측이나 점수 분포로 조정하지 않습니다.
- 모든 단계는 모든 질의에 같은 기준으로 적용합니다 (애매한 질의만 골라 추가 보정하지 않음).
- 시간 안전장치는 경과 시간만 사용합니다.
- 학습은 제공된 4,000쌍과 그 규칙 기반 변형(조건 문구 포함)만, 무료 Kaggle GPU 1장에서 했습니다.

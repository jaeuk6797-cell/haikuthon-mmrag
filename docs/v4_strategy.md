# HAIKUTHON 2026 · v4 제출 모델 정리

> 제출 파일: `sub_v4.zip` (1.0GB) · 구성: SigLIP 검색 → 조건 분해 재정렬 → 학습한 BLIP 판정 → OWL-ViT 위치 검증
> 한 줄 요약: **빠른 모델로 후보를 좁히고, 단계마다 앞 단계가 못 읽는 조건을 전용 방법으로 하나씩 바로잡는다.**

---

## 1. 과제와 제약

| 항목 | 내용 |
|---|---|
| 과제 | 영어 설명(질의) 하나에 정답 이미지 1장. 질의 8,000개 × 후보 이미지 16,000장에서 상위 5장 제출 |
| 점수 | 0.5 × (Recall@1 + NDCG@5) → **1위를 맞히는 것이 가장 중요** (2위는 0.315점) |
| 학습 데이터 | 문장–이미지 4,000쌍 (외부 데이터 금지, LLM·비공개 생성 모델 증강 금지) |
| 채점 서버 | L4 24GB 1장, CPU 4개, 추론 900초 이내 (모델 로딩 제외), ZIP 5GB 이하 |
| 예측 규칙 | 질의마다 독립 예측. 다른 질의의 예측·후보의 원래 설명을 순위 계산에 쓰지 않음 |
| 기준 | 공식 스타터(SigLIP-224, 출력층만 학습) 리더보드 **0.23188** |

## 2. 데이터에서 찾은 핵심 문제

- 이미지가 **형제 묶음**으로 있다: 같은 물체 구성에서 **색의 주인·개수·좌우 위치만 바꾼** 이미지들.
  예) "회색 스카프 + 주황 가방" ↔ "주황 스카프 + 회색 가방"
- 일반 검색 모델(SigLIP)은 문장을 **단어 모음**처럼 읽어서, 단어는 같고 관계만 다른 형제를 잘 구별하지 못한다.
- 검증 결과 **정답은 상위 10장 안에 거의 항상 들어오지만(Hit@20 ≈ 1.0), 1위가 틀리는 것**이 핵심 문제였다.
  → 전략: **검색은 빠르게, 재정렬을 정밀하게.**

## 3. 전체 구조

```
질의 문장 + 후보 이미지 16,000장
   │
 ① SigLIP-base-384 검색 ──────── 16,000장 → 상위 10장                  (빠르고 넓게)
   │
 ② 조건 분해 재정렬 ─────────── 문장을 물체별 조건 12종으로 나눠 10장 재정렬  (세부 조건)
   │
 ③ BLIP ITM 판정 (우리 데이터로 학습) ── 상위 5장을 문장과 함께 정밀 판정      (색 결합·개수)
   │
 ④ OWL-ViT 위치 검증 ─────────── 상위 2장의 물체 위치를 상자 좌표로 비교     (좌우·상하)
   │
 최종 상위 5장
```

원칙: **싼 것은 넓게, 비싼 것은 좁게.** 정밀한 모델일수록 적은 후보만 봐서 900초 안에 끝낸다.

## 4. 단계별 상세

### ① 검색: `google/siglip-base-patch16-384` (학습 없음, Apache-2.0)
- 16,000장을 한 번 읽어 임베딩하고, 질의마다 상위 10장을 고른다.
- 모델 선택 근거 (검증 800질의 + 후보 1,600장):

| 모델 | 점수 | 판단 |
|---|---|---|
| siglip-base-224 (스타터와 같은 모델) | 0.641 | |
| **siglip-base-384** | **0.655** | **선택** |
| siglip2-base-384 | 0.619 | 오히려 낮음 |
| siglip-so400m-384 | 0.675 | +0.02이지만 약 4배 무거워 900초 위험 |
| siglip2-so400m-384 | 0.644 | |

### ② 조건 분해 재정렬 (팀 아이디어, 학습 없음)
- 규칙 파서가 질의 하나에서 **물체별 조건**을 뽑는다. 대상과 방향을 보존한다.
  - 예: (스카프, 회색), (사람 → 스카프, 착용), (컵 → 그릇, 왼쪽)
- 조건 12종: 색, 무늬, 재질, 모양, 상태, 자세, 개수, 색 결합, 개수 결합, 좌우, 상하, 위에 놓임/안
- 조건마다 **대조 문구**를 규칙으로 만든다 ("a gray scarf" vs "an orange scarf").
  - 후보 이미지에 대해 `목표 문구 점수 − 대조 문구 최고 점수`(여백)를 계산해 원래 점수에 더한다.
- 비중 λ = **3.2** (개발 데이터로 결정). 효과: 검증 점수 **+0.058**

### ③ BLIP ITM 판정: `Salesforce/blip-itm-base-coco` (우리 데이터로 학습, BSD-3-Clause)
- 문장과 이미지를 **함께** 읽는 교차 어텐션 모델이다. 상위 **5장**의 일치 점수를 계산해 더한다 (비중 λ = **0.2**, 개발 데이터로 결정).
- **학습 방법 (형제 오답 학습)**
  - 질의마다 정답 1장 + 오답 7장. 오답은 **형제 이미지를 먼저** 넣는다 (오답의 약 80%가 형제).
  - 8장 중 정답을 고르도록 학습한다 (listwise cross-entropy).
  - 문장 쪽(text encoder + ITM head)만 학습하고 이미지 쪽은 고정. 3 epoch, lr 2e-5, 혼합 정밀도, Colab 무료 T4.
  - 제출용은 **4,000쌍 전체**로 학습. 효과 검증은 학습 그룹만으로 학습한 모델로 따로 함.
- 효과: 처음 보는 물체 조합 검증에서 **0.43 → 0.70** (학습 전 → 학습 후)

### ④ OWL-ViT 위치 검증: `google/owlvit-base-patch32` (학습 없음, Apache-2.0)
- 질의에 **물체가 각각 하나인 좌우·상하 관계**가 있으면 (전체 문장의 약 48%), 최종 상위 2장에서 두 물체를 검출한다.
- **상자 중심 좌표**로 관계가 맞는지(+1) / 어긋나는지(−1) / 판단 보류(0)를 정한다.
- **2위가 관계를 더 잘 지킬 때만** 두 장의 순서를 바꾼다. 3위 이하는 그대로 둔다.
- 기준값: 검출 확신도 ≥ **0.1**, 중심 차이 ≥ **0.06** (개발 데이터로 결정)
- 효과 (처음 보는 물체 조합 800질의, BLIP 없는 기준 위):

| | 점수 | R@1 | 1위로 고침 | 1위 놓침 |
|---|---|---|---|---|
| 기준 (SigLIP + 조건) | 0.4897 | 0.3325 | – | – |
| **+ OWL** | **0.5530** | **0.4250** | **77** | **3** |

## 5. 검증 방법 (점수를 믿을 수 있게)

- **그룹 분할:** 같은 물체 구성(형제 묶음)이 학습과 검증에 나뉘어 들어가지 않게 분할했다. 검증 800질의는 **처음 보는 물체 조합**이다.
- **개발 그룹:** 학습 분할 안에서 따로 떼어 낸 그룹으로만 λ, k, 기준값을 정했다. 검증은 마지막에 한 번만 본다.
- **고친 수 / 망친 수**를 함께 기록해서, 평균 점수뿐 아니라 실제로 무엇이 바뀌었는지 확인했다.
- 제출 전 **모의 테스트:** 서버와 같은 형식으로, 새 프로세스에서 인터넷과 캐시 없이 ZIP 폴더만으로 실행해 형식을 검사했다.

## 6. 규칙 준수

- 추론은 **로컬 공개 모델만** 사용한다 (외부 API 없음). 라이선스: SigLIP·OWL-ViT Apache-2.0, BLIP BSD-3-Clause.
- 학습은 **무료 Colab GPU**에서만, 제공된 4,000쌍만 사용했다. 외부 데이터와 LLM 증강은 없다.
- **질의마다 독립 예측.** 다른 질의의 결과로 보정하거나 후보 이미지의 원래 설명을 쓰지 않는다.
- 대조 문구는 **규칙으로 만든 점검용 문구**이며, 학습 데이터 증강에 쓰지 않았다.

## 7. 900초를 지키는 장치

| 장치 | 내용 |
|---|---|
| 이미지 한 번만 읽기 | 16,000장을 한 번 디코딩해 SigLIP 임베딩과 BLIP용 축소본(GPU 보관)을 함께 만든다 |
| BLIP 묶음 처리 | 같은 1위 후보를 보는 질의끼리 묶어 이미지 특징 계산을 재사용한다 (결과는 질의마다 독립) |
| OWL 이미지 재사용 | 이미지마다 한 번만 검출하고, 그 이미지를 보는 질의들이 결과를 공유한다 |
| 시간 안전장치 | 이미지 처리가 400초를 넘으면 BLIP을 건너뛴다. OWL 예상 시간이 830초 예산을 넘으면 OWL을 건너뛴다. **이미지 처리 직후 한 번만 정해 모든 질의에 똑같이 적용**한다 |

## 8. ZIP 구성

```
sub_v4.zip
├── model.py                      ← load_model / predict (검색 → 조건 → BLIP → OWL)
├── requirements.txt              ← transformers==5.22.2, safetensors==0.8.0, sentencepiece==0.2.3, pillow==13.0.0
├── haiku/                        ← 규칙 파서(siblings.py), 조건 재정렬(rerank.py), OWL 규칙(owl.py)
└── models/
    ├── siglip/   (408MB, fp16)
    ├── blip/     (448MB, fp16, 4,000쌍으로 학습)
    ├── owl/      (310MB, fp16)
    └── haiku_config.json
```

`haiku_config.json`

```json
{"K": 10, "method": "B", "lam": 3.2,
 "kinds": ["color","pattern","material","shape","state","pose","count","color_binding","count_binding",
           "relation_left_right","relation_above_below","relation_on_inside"],
 "itm": {"use": true, "k": 5, "lam": 0.2, "tau": null, "skip_after_sec": 400},
 "owl": {"use": true, "thr": 0.1, "margin": 0.06, "budget_sec": 830, "cost_factor": 3.0}}
```

## 10. 한계와 다음 단계 (v5 후보)

- OWL은 **물체가 하나씩인 좌우·상하**만 다루고, **상위 2장**만 바꾼다.
- 같은 종류 물체가 여러 개인 문장(약 12%)과 다른 관계(위에 놓임·안·옆 등)는 아직 확인하지 않는다.
- 실험 중인 후보:
  - **OWL 확장:** 위에 놓임·안·타고 있음·옆을 상자 규칙으로 확인
  - **물체별 색 비교:** 물체 영역만 잘라 색을 확인 (속성을 정확한 대상에 연결)
  - **오답 구조 분석:** v4가 끝까지 틀리는 문장 유형 확인

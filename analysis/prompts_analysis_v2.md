# 프롬프트 구조 분석 2차 (텍스트만)

- 대상: `prompts.jsonl` 4,000개 전수 (2026-11-21 기준)
- 재현: `python analysis/analyze_prompts_v2.py path/to/prompts.jsonl` (1~2초)
- 모두 정규식/어휘 기반 근사치. 이미지는 일부 샘플만 눈으로 확인
- 1차 분석(`prompts_analysis.txt`)은 그대로 두고, 이 문서는 객체 단위로 더 들어간 결과

## 1. 어휘와 문장 변형
- 전체 어휘 587단어 (3회 이하 등장 52개)
- 문장 뼈대(함수어만 남기고 치환)가 3,998종 → 속성 어휘는 적지만 서술 방식은 거의 다 다름
  - 같은 뜻의 표현이 여러 가지: "one black glove" / "one glove, black," / "one glove that is black"
  - 스타일·시점·장소를 문장 맨 앞에 쓰기도 하고 맨 뒤에 쓰기도 함
- 시사점: 템플릿 파싱·규칙 기반 매칭은 불안정. 문장 구조와 관계 방향을 이해하는 임베딩이 필요

## 2. 장면 수준 필드 (프롬프트당 거의 1개)
- 스타일: photograph 792, 3D render 596, flat illustration 420, watercolor 392, oil painting 304, colored-pencil 300, gouache 300, low-poly 3D 208, paper-cut collage 204, clay-style 3D 200, pencil sketch 148, ink 148
- 시점: overhead 1,316, front 951, oblique 912, side 823
- 조명: side 1,012 / warm indoor 1,004 / soft diffuse 1,002 / direct sunlight 980
- 장소: studio 49%, farm, park, living room, garden 등
- 이 필드들은 값이 몇 개뿐이라 이미지 전체 분위기로 구분 가능. 정답을 가르는 건 객체 쪽 정보

## 3. 객체 수준
객체 = "one/two/three/single + 명사"로 소개된 구절. 총 11,326개(프롬프트당 2.83개).

### 속성 (색, 무늬, 재질, 모양, 상태, 자세)
| 항목 | 엄격(소개 구절만) | 관대(프롬프트 내 같은 명사 전체) |
|---|---|---|
| 속성 하나도 없음 | 24.9% | 22.7% |
| 색 있음 | 60.1% | 62.3% |
| 무늬 | 11.4% | 12.3% |
| 재질 | 6.7% | 7.1% |
| 자세 | 11.0% | 11.3% |

- 사람 객체는 색이 거의 없고(806개 중 2개) 자세로만 묘사됨. 색은 scarf, shirt 같은 옷에 붙음
- 모든 객체에 색이 있는 프롬프트 34~36%, 색 있는 객체가 하나도 없는 프롬프트 14~15%
- 두 단어 명사(bonsai tree, tape measure, roller skate, loaf of bread)는 속성을 놓치므로 "속성 없음"이 다소 부풀려졌을 수 있음 (실제 20% 안팎 가능성)

### 관계: 위치와 행위를 구분
- 위치(spatial): left/right of, next to, above, below, inside, on top of, resting on 등
- 행위(action): holds, wears, rides

| 대상 | 위치만 | 행위만 | 둘 다 | 없음 |
|---|---|---|---|---|
| 전체 객체 (11,326) | 72.6% | 4.5% | 13.2% | 9.8% |
| 사람 (806) | 8.8% | 12.7% | 77.8% | 0.7% |
| 사람 제외 (10,520) | 77.5% | 3.9% | 8.2% | 10.5% |

- 프롬프트 단위로는 위치 관계 있음 96.4%, 행위 관계 있음 18.6%
- left/right가 들어간 프롬프트가 약 42%. 방향 이해가 점수에 크게 영향을 줄 가능성
- 사람 객체는 거의 항상 행위 관계에 엮임 (옷·장비를 입고 타는 장면)

### 속성 × 관계 (관대 기준)
| 구분 | 비율 |
|---|---|
| 속성 + 관계 | 70.0% |
| 속성만 | 7.3% |
| 관계만 | 20.2% |
| 둘 다 없음 | 2.5% |

- 속성이 없어도 대부분은 관계로 구분됨. 속성도 관계도 없는 객체는 약 280개(2.5%)
- 모든 객체가 속성 또는 관계를 가진 프롬프트가 93%

### 관계 문장에 안 나오는 객체 (1,106개, 9.8%)
- 대부분 "One cat is also in the living room."(also present), 나열("one rake, and one dog"), 속성만 서술("One spoon is black.") 형태
- 명사: book, rabbit, boot, bear, parrot, dog, bonsai ... 동물·일상 사물에 고르게 분포
- 이미지 4장 확인: 이런 객체도 실제 이미지에서 크고 뚜렷하게 그려져 있음 (예: 전경의 장미, 오른쪽의 소나무)
- 3247번 이미지: 프롬프트에 없는 속성(장미 빨강, 공 흰색/주황)이 이미지에서는 구체적으로 정해져 있음 → 프롬프트에 안 쓴 속성은 구분 단서가 아님

## 4. 어려운 오답(hard negative) 추정
- 객체 종류 집합은 680종뿐 (명사 목록 기준). 집합별 프롬프트 수가 4개(319집합)와 8개(291집합)에 몰림 → 같은 객체 조합에서 속성·관계·장면만 바꿔 4~8개씩 생성했을 가능성 (추정)
- 4,000장 풀에서 어떤 프롬프트와 객체 집합이 같은 다른 프롬프트: 평균 6.1개(최대 27), 객체 절반 이상 겹치는 프롬프트: 평균 18개 (600개 표본)
- 평가 풀이 16,000장이고 같은 방식으로 만들어졌다면 약 4배: 동일 객체 후보 약 24개, 유사 후보 약 72개 (가정: train과 같은 분포)
- 결론: 객체 종류만 맞추는 모델은 Recall@1이 크게 떨어질 것. 색·무늬·개수·방향 관계의 결합이 점수를 좌우

## 5. 이미지 디코딩 속도 (임시 측정)
- 무작위 40장: PNG 한 장 평균 33ms, 평균 파일 크기 약 839KB (768×768)
- 단일 프로세스로 16,000장이면 약 534초(9분). 측정 VM 기준이라 평가 서버(L4)와 다를 수 있음
- 추론 제한 15분(인덱싱 포함)이라 병렬 로딩이 필요할 가능성 → 노트북에서 재측정 필요

## 6. 아이디어 (아직 검증 안 함)
- 1단계 전체 검색(파인튜닝한 SigLIP 계열) → 2단계 재순위(객체 존재 / 속성 / 방향 관계 점수)
- 같은 객체 집합 안에서 속성·방향만 다른 프롬프트/이미지를 한 배치에 묶는 hard negative 학습
- 이미지 임베딩은 한 번만 계산하고, 객체별 점수는 같은 임베딩/패치 특징에서 뽑아 시간 제한을 지킴
- 규칙: 외부 LLM으로 train 증강 금지, 외부 API 호출 금지. 정규식 파싱은 애매하면 운영진에 문의
- 먼저 `notebooks/baseline_kaggle.ipynb`로 기준선 오답을 유형별(객체/속성/방향)로 분해해 우선순위를 정할 것
